# Обнаружение препятствий перед беспилотным поездом метро по 3D-лидару

Система отвечает на вопрос «есть ли что-нибудь на пути поезда, чего там быть
не должно» по потоку PointCloud2: строит габаритный коридор движения (ось
пути → стены тоннеля → штатные конструкции) и объявляет препятствием всё, что
осталось необъяснённым внутри габарита. Без ML и без обучения на записях —
поэтому работает на данных, которых не видела (требование ТЗ по
обобщаемости).

Среда по ТЗ: **Ubuntu 22.04 + ROS 2 Humble + Docker**. Решение поставляется
образом `guard_detector` и не требует ручной установки зависимостей.

## Выход системы

- **препятствие обнаружено / не обнаружено** — маркеры и статус;
- **расстояние до ближайшего препятствия** — `nearest_m` в `/guard/status`;
- продвинутый выход: положение (дальность, боковой сдвиг), размеры (ш×в),
  принадлежность габариту, подтверждённость межкадровым треком.

## Быстрый старт (сценарий демонстрации по ТЗ)

```bash
# 1. Сборка образа (контекст — корень репозитория)
docker build -f pavel/deploy/Dockerfile -t guard_detector .

# 2-3. Запуск: нода + проигрывание bag-файла одной командой
docker run --rm -v "$PWD/for_hackathon/doubleT_obstacle:/data/doubleT_obstacle" \
    guard_detector ros2 launch guard_detector guard.launch.py \
    topic:=/sensing/lidar/hesai128/pointcloud bag:=/data/doubleT_obstacle
```

4-5. Лидарные данные и результат (второй сессией в том же контейнере:
`docker exec -it <id> bash -c 'source /opt/ros/humble/setup.bash && bash'`):

```bash
ros2 topic echo /guard/status --once -l 5000   # JSON: fps, latency, reach, nearest_m
ros2 topic hz  /guard/status                   # частота обработки, цель ~10 Гц
ros2 topic echo /guard/obstacles --once        # маркеры: дальность, lat, размер, confirmed
```

Для визуализации — RViz2 (Fixed Frame = фрейм лидара; PointCloud2 топика
лидара + MarkerArray `/guard/obstacles` и `/guard/corridor`) либо встроенный
веб-вьюер (см. ниже). Подробности, параметры, ловушки QoS —
`pavel/deploy/README.md`.

## Архитектура

```
ROS 2 bag (PointCloud2, ~10 Гц)
   → guard_node (ros2_ws/src/guard_detector)          # подписка RELIABLE/KEEP_LAST(1)
   → guard.run.analyze (pavel/guard, numpy/scipy):
       блок 1   track.py       ось пути по головкам рельсов (полилиния)
       блок 1б  axis_wall.py   ведение оси вдаль: где рельсы кончаются — стена
       блок 1в  wall_rules.py  режимы оси по бинам (rails/center/lead/hold),
                              кривизна ограничена нормой СП 32-105 (R ≥ 150 м)
       блок 2   walls.py       внешняя граница коридора — стены тоннеля
       блок 2б  structures.py  штатные конструкции (ниши, лотки, свод, полотно)
       блок 3   obstacles.py   препятствия = необъяснённый остаток в габарите
                              (+ темпоральный фон: «вчера тут было пусто»,
                              + накопление остатка за 8 кадров для мелких
                              дальних объектов)
       блок 3.5 tracker.py     межкадровый трекинг в мировых координатах
                              (подтверждение, гейты с ходом поезда, анти-FP
                              по мировой статичности)
   → топики: /guard/obstacles (MarkerArray), /guard/corridor, /guard/status (JSON)
   → визуализация: RViz2 или веб-вьюер (web_viewer.py + web/)
```

Полное описание тракта с замерами по блокам — `pavel/README.md`.

## Описание алгоритма (кратко)

- **Какую проблему решает.** В тоннеле почти нет размеченных примеров
  препятствий, а «норма» однотипна. Поэтому вместо классификации объектов
  система **описывает нормальный тоннель** (ось, стены, конструкции) и ищет
  всё, что в него не вписывается внутри габарита движения.
- **Данные.** Облако точек одного кадра (x вправо, y назад, z вверх; внутри:
  fwd=−y, lat=x, up=z) + одометрия записи (для трекера и темпорального фона).
- **Решение о препятствии.** Кластер остатка в габарите становится находкой,
  если проходит правила-объяснения (стена/пыль/фрагмент/опора/колонна);
  тревога — после подтверждения треком (повторяемость в мировых координатах)
  или масс-эскалации (повторная массивная находка; однокадровый транзиент
  не подтверждается никогда).
- **Пороги не подогнаны под записи**: каждый выведен из нормы (габарит,
  колея 1520 мм, СП 32-105, ГОСТ 23961-80), физики датчика (угловое
  разрешение лидара) или измеренного плато с комментарием-замером в коде.
- **Ограничения.** Мелкий объект 0.3×0.3 м физически даёт 2-6 точек на
  60-90 м — покадрово это ниже порога, ловится накоплением; объект,
  присутствующий с первого кадра записи и неподвижный, темпоральному фону
  нечем опровергнуть (лечится картой повторного рейса).

## Параметры и конфигурация

Launch-аргументы ноды (`pavel/deploy/README.md` — полная таблица):

| параметр | умолчание | что |
|---|---|---|
| `topic` | `/lidar_points` | топик PointCloud2 (для doubleT_obstacle — `/sensing/lidar/hesai128/pointcloud`) |
| `bag` | — | каталог записи внутри контейнера (монтируется в `/data`) |

| `frames` | 20 | окно усреднения fps/латентности |
| `publish_corridor` | true | публиковать линии габарита для RViz |

Габарит движения — ширина 2.1 м (±1.05 м от оси, кламп `GAUGE_HALF_CHECK`),
высота 3.0 м над полом (`GAUGE_H_HI`); внешний коридор коридорной оценки
шире (±1.50 м, `GAUGE_HALF`). Константы — `pavel/guard/walls.py`.

## Эксперименты (замеры)

- **Дальность**: человек на путях (doubleT_obstacle) — стабильная находка на
  **52-58 м**, подтверждённая треком (красный маркер); мелкий объект 0.3 м в
  габарите — от ~65 м (накопление остатка за 8 кадров); контроль коридора
  (reach) — 60-130 м в зависимости от участка.
- **Задержка/скорость**: `analyze` ~85 мс медиана на кадре ~346 тыс. точек
  (замер в контейнере, `pavel/deploy/README.md`); на 5 записях ~190 тыс.
  точек — быстрее. Бюджет 10 Гц выдержан по медиане.
- **Ложные срабатывания**: FP-семьи «опоры контактного рельса» и «дальний
  шум за reach» сняты правилом мировой статичности трека и флагом
  `beyond_reach`; однокадровые вспышки показываются янтарным, не красным.
- **Сложные ситуации (честно)**: длинный низкий объект на полотне
  геометрически неотличим от рельса в одном кадре — ловится темпоральным
  фоном; свисающий кабель выше 3.0 м — вне габарита по норме, не детектируется
  намеренно.
- Разбор итераций (что не сработало и почему) — `pavel/README.md`,
  `docs/detector-results.md`.

## Интерпретация результатов (что считать препятствием)

Не всякая подсвеченная находка — препятствие. Иерархия уровней:

- **Красная тревога** («⚠ ПРЕПЯТСТВИЕ: N м») — находка в габарите поезда,
  подтверждённая межкадровым треком, в пределах измеренного коридора.
  Только этот уровень является детекцией по смыслу задачи.
- **Янтарная «за reach»** — подтверждённый треком объект за пределами
  подтверждённого коридора (коридор там не измерен — зона неизвестна, а не
  занята): раннее предупреждение, не тревога.
- **Оранжевый** — объект вне габарита поезда (инфраструктура у пути):
  обзорная информация, в оценку не входит.
- **Однокадровые неподтверждённые** — по умолчанию скрыты: транзиент,
  живущий 1-3 кадра, — почти всегда шум сенсора.

Известные источники ложных подтверждений (предельно честно):

- **Срыв оси/коридора** — если ось пути на кадре измерена неверно (редко:
  разреженная дальняя зона, нештатная геометрия), габарит смещается с пути и
  в него попадает штатное. Следствие: кластер подтверждений на одном участке
  при «улетевшей» оси. Диагностируется по виду сверху: белая рамка габарита
  должна идти по колее.
- **Инфраструктура у кромки габарита** — сборка контактного рельса, борта
  платформ, пороги ворот геометрически частично в габарите на кривых;
  отделяются от препятствий нормативным сечением, но на пределе.
- **Предел дальности**: дальше ~60-90 м мелкий объект даёт единицы точек —
  там действует только накопление; одиночных дальних вспышек без
  подтверждения треком в выдаче нет по построению.

Практическое правило чтения веб-вьюера: оценивать решение по красному уровню
и по числу кадров эпизода (реальный объект держится непрерывно от дальнего
захвата до проезда; шум — нет).

## Веб-вьюер (демо и разметка, без ROS и Docker)

```bash
python3 web_viewer.py for_hackathon            # все записи, порт 8765
```

Браузерный просмотр облака (three.js): воспроизведение, зоны, рельсы, вид
сверху, слой «Габарит (guard)» — коридор/стены/ось/препятствия с подсветкой
подтверждённых тревог. Запись можно **загрузить прямо из браузера** (блок
«Данные» → перетащить `*.db3` + `metadata.yaml`), затем кнопкой «Посчитать
guard для этой записи» — детекция появится в слое без командной строки.

Режим «Разметка»: клик по облаку предлагает габарит объекта, бокс правится
мышью, сохранение в `labels/` (формат — `labels/README.md`). На разметке
строится датасет (`tools/build_dataset.py`) и оценка recall/precision
(`validation/dataset_eval.py`, CSV в `validation/out/`).

## Данные

ROS 2 bag (Hesai LiDAR, ~10 Гц, PointCloud2: x, y, z, intensity, ring,
timestamp). Разработочные записи в `for_hackathon/`:

| bag | кадров | длительность | топик |
|---|---:|---:|---|
| `doubleT_obstacle` (человек на путях) | 201 | 20.4 с | `/sensing/lidar/hesai128/pointcloud` |
| `doubleT_platform` | 345 | 34.4 с | `/lidar_points` |
| `roundT_doubleT` | 252 | 25.1 с | `/lidar_points` |
| `roundT_pressureGate_roundT` | 268 | 26.7 с | `/lidar_points` |
| `roundT_squareT_pressureGate_squareT` | 545 | 55.4 с | `/lidar_points` |
| `squareT_platform_squareT_switch` | 877 | 88.2 с | `/lidar_points` |

Сокращения: `roundT`/`doubleT`/`squareT` — форма стрелки, `platform` —
перрон, `pressureGate` — напорные ворота, `switch` — стрелочный перевод,
`obstacle` — препятствие на пути.

## Требования для разработки (вне Docker)

Python **3.12 или ниже** (на 3.13 нет wheel для open3d — он нужен только
офлайн-скриптам `visualize_bag.py`/`snapshot.py`; нода и вьюер его не
используют):

```bash
pip install numpy open3d laspy scikit-learn
```

Полезные утилиты: `visualize_bag.py` (покадровая анимация bag в Open3D),
`snapshot.py` (один кадр в 3D), `trim_bag.py` (прореживание bag),
`precompute_track.py` (предрасчёт геометрии пути для вьюера),
`cd pavel && python -m guard.run ../for_hackathon/<запись> --frame N
--polyline` (один кадр тракта в консоль), `python -m guard.export_web
../for_hackathon/<запись>` (предрасчёт guard-слоя для вьюера).
