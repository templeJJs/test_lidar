# Кто чем владеет (карта порядка)

Дата: 2026-09-15. Причина файла: в одном рабочем дереве работают **два агента**, и без явных границ
правки затирают друг друга. Ниже — кто владеет какими файлами, где именно лежат «чужие» вставки
и какое правило действует.

## Правило

**Один файл — один правщик одновременно.** Перед тем как переписать общий файл целиком, посмотри
раздел «Наши вставки в их файлах» ниже: там перечислено, что потеряется. Если потеря неизбежна —
сначала предупредить, потом переписывать.

## Наши вставки в их файлах

Если файл будет переписан целиком, потеряется следующее (искать по этим признакам):

**`web_viewer.py`**
- маршрут `GET /track` — отдаёт JSON из `track_geometry.build_track` (с кэшем по `bag`+`frame`);
- маршрут `GET /track3d.js` — раздача нового статического файла;
- строка `'track3d.js'` в списке `WEB_ASSETS` (хеширование для авто-перезагрузки);
- класс `TrackGeometry` и строка `LAYER` в стартовом логе;
- маршрут `GET /labels` — только метки зон кадра (заголовок 12 байт, в `reserved` — `axis_frame`,
  затем `n` байт uint8). Нужен, чтобы после загрузки геометрии кадра перекрасить точки по **его**
  оси: `/frame` считается до геометрии и иначе берёт ось другого кадра;
- `Viewer.label_bytes(idx)` — тело этого маршрута;
- `RailZone(track, bag_name, db_path)` и флаг `allow_build` у `lines`/`mask`/`labels`: при
  `allow_build=True` недостающая геометрия кадра собирается через `TrackGeometry.json_bytes`
  (у `/frame` он остаётся `False` — на `/frame` сборки нет, как и раньше).

**`web/app.js`**
- мягкий импорт слоя в начале файла: `let createTrackLayer = null; try { … await import('./track3d.js') } catch {…}`;
- все обращения к слою — под проверкой `trackLayer &&` (загрузка при смене кадра, тумблеры, «чистое
  поле», пресеты, галочка автовида);
- ветка «слоя нет»: `showTrackUnavailable(...)` — пишет причину в HUD и подписи кнопок;
- пресет `['track', 'Объекты пути']` и решение о стартовой камере (при включённом автовиде пресет
  «От лидара» не применяется);
- `fetchLabels` / `relabelAfterTrack` / `applyLabels` (`about` строк 449–491) и вызов перекраски в
  `showFrame` после `trackLayer.load` (защита от гонки по `state.idx`/`state.bag`); в `prefetch()`
  добавлен прогрев геометрии `trackLayer.prefetch(meta.bag, idx)`.

**`web/track3d.js`** (наш файл)
- метод `prefetch(bag, idx)` — прогрев серверного кэша `/track` для кадров вперёд (LRU на 8 кадров,
  не больше одной предзагрузки в полёте), экспортируется наружу и сбрасывается в `reset()`.

**`web/index.html`**
- группа «Объекты пути (3D)»: `t-points`, `t-rails`, `t-sleepers`, `t-floor`, `t-startview`, кнопки
  «Чистое поле» и «Профиль рельса», строка `#cameraNote`;
- компактный HUD (`#hudTop`, `#hudFrame`) и свёрнутые блоки `<details class="notes">`
  («Подробности кадра», «Откуда числа»);
- CSS: скрытие полос прокрутки панели, `overflow-x: hidden`, перенос длинных строк, сжимаемые плашки `.src`.

## Текущее состояние (незакоммиченное)

- параллельный агент: 8 файлов `app/client/src/**` + новые `api/pathTunnel.ts`, `viewer/path.ts`,
  а также `zones.py`, `tests/test_zones.py`;
- наши: `web/track3d.js` (новый), `track_geometry.py`, `check_track_geometry.py` (изменены),
  `web/app.js`, `web/index.html`, `web_viewer.py` (содержат и наши, и их правки).

**Почему мы не коммитим прямо сейчас:** общие файлы содержат обе линии работы, и любой коммит
подпишет чужие изменения нашим сообщением. Порядок такой: сначала коммитит параллельный агент свою
часть, затем мы — свою, отдельным коммитом.

## Что можно удалить (по согласованию)

- `.scratch/` — 125 файлов, 27 МБ (пробы, дампы кадров, логи прогонов);
- `track3d.py`, `web3d/` — прототип, перенесённый в `web/`; нужен только как справка.
  Перед удалением закоммитить, чтобы осталась история.
