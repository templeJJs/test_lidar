# Детектор препятствий: результаты на данных `for_hackathon/`

Всё измерено на 6 записях × 5 кадров (0/50/100/150/200) на том же стенде, где
собирался `detector/`. Алгоритм и обоснование порогов — `docs/detector-algorithm.md`.

Команды:

```bash
python -m unittest discover -s tests -q       # тесты, включая tests/test_detector_core.py
```

То же самое на прямой `x = s·y + i` — доказывает, что дело именно в локальной оси:

|---|---|

| doubleT_platform | 0 0 0 0 **4** |
| roundT_doubleT | 0 **2** 0 0 **1** |
| roundT_pressureGate_roundT | 0 0 **5** 0 **1** |
| roundT_squareT_pressureGate_squareT | 0 0 0 0 0 |
| squareT_platform_squareT_switch | 0 0 0 0 0 |

**Итого: 13 ложных бинов** против 0 на локальной оси.

### Контроль: локальная ось без ограничения дальности

Если не ограничивать дальность участком измеренной оси, ложных бинов **22**:
за 15 м продолжения линейная экстраполяция на кривой уводит габарит. Это и есть
причина ограничения.

## 2. Полнота: внесённый объект

Настоящих объектов в записях нет, поэтому полнота измеряется внесением
синтетического объекта — вертикальной плиты 0.70 × 1.60 м в габарите, точки на
обращённой к датчику поверхности (`detector.core.synthetic_object`).

| проверка | результат |
|---|---|
| плита 0.7 × 1.6 м, 4 записи × дистанции 12/20/30 м | **18/18 найдено** |
| ошибка дистанции | ≤ 0.15 м |
| плита при смещении от оси u = 0 / ±0.3 / ±0.6 м | найдена на всех |
| плита при u = ±0.8 м | **не найдена** (край в 0.15 м от границы габарита) |
| стена вдоль пути, заходящая в габарит краем (6 записей) | **6/6 не найдена** |
| рельсы, корыто, ложе, лоток, свод, стена за габаритом (синтетика) | не найдены |

Плита при `u = ±0.8` — осознанный размен порога 0.18 м, см. алгоритм.

## 3. Скорость

30 повторов на кадр, после разогрева, один поток:

| запись | точек | медиана, мс | p95, мс | макс, мс |
|---|---|---|---|---|
| doubleT_obstacle | 346808 | **8.82** | 10.39 | 10.65 |
| doubleT_platform | 185638 | 7.76 | 9.99 | 10.10 |
| roundT_doubleT | 189502 | 5.07 | 5.77 | 6.18 |
| roundT_pressureGate_roundT | 189864 | 8.23 | 9.80 | 10.18 |
| roundT_squareT_pressureGate_squareT | 185070 | 4.48 | 5.67 | 6.27 |
| squareT_platform_squareT_switch | 181792 | 12.47 | 13.85 | 14.39 |
| **все** | 158k–347k | **7.91** | 12.89 | 14.39 |

Бюджет ТЗ — 10 Гц (100 мс) на весь горячий контур. Ядро на самом большом кадре
(347 тыс. точек) — **8.8 мс медиана, 10.7 мс максимум**, то есть ≤ 30 мс с запасом
3×. Разбор и парсинг CDR (`bag_reader`, ~40 мс на 24 МБ сообщение) в это не входят
и в сумме с ядром дают ~50 мс — вдвое меньше бюджета.

Ускорение ×2.5 против первой версии получено отсечкой по X и Z **до** интерполяции
оси: интерполяция полилинии на 347 тыс. точек стоит 22 мс, после отсечки остаётся
3..20 % точек.

## 4. Дальность (жёсткое ограничение данными)

Замерено по объёму пути (полуширина 1.36 м, высота 0.26..3.86 м над полом):

| размер объекта | уверенная дальность |
|---|---|
| 0.3 м | ~40–50 м |
| 0.5 м | ~60–80 м |
| 1.0 м | ~80–100 м |
| «в объёме пути за 137 м точек нет вообще» | — |
| 100–150 м | 0.0–0.6 точки/м |

Целевые 200/300 м из ТЗ **этими данными недостижимы**: лидар возвращает
единичные точки на такой дальности, и объект в 0.3 м там не различим ни при каком
алгоритме. Детектор честно сообщает свою дальность в диагностике
(`max_data_range_m`, `corridor_max_range_m`) и ограничивает работу участком, где
ось достоверна.

## 5. Дальний контур (стены/свод) — реализован, но не включён

Единственный путь к дальней дальности. Результаты:

| запись | свод, м | левая стена, м | правая стена, м | свободная ширина, м | «отклонений» на 26 кадрах |
|---|---|---|---|---|---|
| doubleT_obstacle | 4.22 | −2.79 | 2.92 | 3.2–12.2 | **8** |
| doubleT_platform | 4.25 | −2.37 | 1.83 | 2.8–12.2 | 928 |
| roundT_doubleT | 4.12 | −3.54 | 2.29 | 3.2–12.2 | 975 |
| roundT_pressureGate_roundT | 4.27 | −2.68 | 2.42 | 0.1–12.2 | 985 |
| roundT_squareT_pressureGate_squareT | 4.07 | −2.26 | 2.40 | 2.7–12.2 | 731 |
| squareT_platform_squareT_switch | 3.95 | −2.45 | 2.25 | 2.8–12.2 | 325 |

* свод устойчив: 3.95..4.27 м по всем записям — согласуется с эталоном 4.18..4.43 м;
* стена `doubleT_obstacle` повторяется с точностью **15–18 мм СКО** по кадрам —
  там дальний контур даёт 8 событий на 26 кадров и практически пригоден;
* на остальных записях — сотни событий: датчик между кадрами поворачивался
  (рыскание до 4.1°), а на 100 м поворот на 4.1° смещает стену на метры.

Поэтому дальний контур **выключен по умолчанию** и требует компенсации рыскания.

## 6. Чего не проверено

* **Docker и ROS 2 вживую не запускались** — по решению заказчика упаковка снята
  с текущего этапа. Пакет `ros2_ws/src/tunnel_detector/` и `docker/` лежат
  готовыми, но сценарий `docker build → ros2 bag play` не прогонялся.
* **Полнота на реальных объектах не измерена** — в предоставленных записях их нет,
  использован внесённый объект. Реальный объект (человек, предмет) может давать
  меньше точек при той же высоте.
* **Движущиеся объекты** не проверялись: разметки нет.
* **Робastность к дождю/пыли/грязи на оптике** не проверялась.
* Дальний контур на записях с движением датчика не доведён (см. раздел 5).

## 7. Запуск

```bash
# тесты (в том числе ядра детектора)
python -m unittest discover -s tests -q

# один кадр записи
python -c "import bag_reader, detector, json; \
  bf = bag_reader.BagFrames('for_hackathon/roundT_doubleT/roundT_doubleT_0.db3'); \
  m = detector.model_for_db('for_hackathon/roundT_doubleT/roundT_doubleT_0.db3'); \
  print(json.dumps(detector.detect(bf[0].xyz, model=m).to_dict(), ensure_ascii=False))"
```
