# Линия хода и туннель безопасности — дизайн

Дата: 2026-09-15. Область: вьюер облака точек лидара (`web_viewer.py` + `zones.py` +
клиент `app/client`), данные `for_hackathon/doubleT_obstacle` (201 кадр, 346 808
точек/кадр, колея 1520 мм, туннель метро).

## Зачем

1. **Линия хода** — полилиния в 3D, идущая по пути вперёд и повторяющая изгибы
   (стрелки, кривые). Как «маршрут» у беспилотников: сразу видно, куда ведёт путь.
   Включается/выключается, можно сравнить три источника линии разом.
2. **Туннель безопасности** — объём, заметаемый габаритом вагона метро вдоль линии
   хода. Всё, что попало внутрь, — помеха, которую нужно детектить. Нынешний
   плоский коридор `±1.06 м` уже полуширины вагона `1.36 м`, то есть помеху в
   1.1…1.35 м от оси он пропускает.

## Установленные факты (нормативы, не догадки)

| параметр | значение | источник |
|---|---|---|
| габарит подвижного состава метро «М» | 2700 мм ширина × 3750 мм высота | ГОСТ 23961-80 |
| вагоны 81-717/714 | 2670 мм (по заводу 2712) × 3650 мм | техданные ММЗ |
| вагоны 81-760/761 «Ока» | 2686 × 3680 мм | техданные |
| отсчёт ширина / высота | от **оси пути** / от **уровня головки рельса (УГР)** | ГОСТ 23961-80 |
| контактный рельс | 1450 мм от оси, рабочая поверхность **160 мм над УГР**, укладка **слева** по ходу | ПТЭ метрополитенов, п. 3.26 |
| низ вагона | редуктор 45 мм над УГР внутри колеи; низ кузова 940 мм вне колеи | Комментарии к ПТЭ |
| край платформы | 1457 мм от оси, 1100 мм над УГР | ГОСТ 23961-80, табл. 3 |

Расхождения в текущем коде (`zones.py`), которые правятся этой работой:

- `contact_height = 0.20` над полом = 40 мм над УГР вместо 160 мм (нужно ≈0.32 над полом);
- `contact_offset = 1.46` против нормы 1.45 (10 мм — приводим к норме);
- `contact_side = +1`, а в метро контактный укладывают слева по ходу (меняем дефолт на −1).

## Линия хода

Высота линии — **на уровне головки рельса**: `z = z_пол(y) + RAIL_HEIGHT` (0.16 м).
Длина — **вперёд на всю анализируемую дальность** (`--analysis-dist`, по умолчанию
40 м; это базовая настройка), шаг узлов 1 м. Узлы — только там, где есть данные.

Три источника, все три считаются сразу, в клиенте переключаются (плюс режим
«сравнение» — все три разными цветами одновременно):

| вариант | что это | как считается |
|---|---|---|
| `corridor` | центр свободного коридора по бинам | для каждого бина 1 м по Y: центр самого широкого свободного интервала в полосе между стенами; сглаживание 3 бина по медиане; если бин занят — берём предыдущее значение |
| `rails` | ось измеренных головок рельсов | `track_geometry.build_track(db, frame)['axis']` → `x = s*y + i` (линейная модель). Если модуль недоступен или падает — вариант помечается `unavailable`, вьюер не падает |
| `axis` | прямая по оси из панели | `x = params.axis_x` на всех узлах |

Вырожденные случаи: если `corridor` не нашёл свободного интервала ни в одном бине —
отдаём `null` для варианта (клиент показывает «нет данных»).

## Туннель безопасности

Объём = прямоугольное сечение, заметаемое вдоль выбранной линии хода:

- полуширина **±1.36 м** (полуширина самого широкого вагона 2712/2), слайдер 1.30…1.60;
- низ **0.10 м над УГР**, верх **3.70 м над УГР** (габарит М 3.75, вагоны ≤3.68);
- вдоль — по узлам линии хода (то есть с поворотами), бины 1 м.

Из объёма **исключается известное оборудование**, иначе оно само станет помехой:

- ходовые рельсы: полоса `|x − x_рельса| ≤ rail_half_width` в диапазоне высот рельса;
- контактный рельс: полоса `|x − x_контактного| ≤ 0.15 м` в диапазоне ±0.20 м вокруг
  его нормальной высоты (160 мм над УГР);
- шпалы и балласт ниже 0.10 м над УГР (то есть порог сам отсекает);
- край платформы: если в бине есть точки в полосе 1.40…1.55 м от оси на высоте
  1.0…1.2 м над УГР — бин помечается `platform` и помехой не считается.

Занятость бина — тот же проверенный критерий, что и раньше: точек **не меньше
`--obstacle-points`** (20) **и** размах по высоте (перцентили 5…95) **не меньше
`--obstacle-height`** (0.5 м). Это отсекает кромку балласта и кабельные лотки.

Отрисовка: каркас туннеля (рёбра каждые 2 м) полупрозрачным цветом, точки внутри
объёма — красным, занятые участки — списком в HUD в метрах вдоль пути.

## API

`GET /meta` получает два новых блока (остальное не меняется):

```json
"path": {
  "step": 1.0,
  "z_offset": 0.16,
  "variants": {
    "corridor": {"y": [...], "x": [...], "z": [...], "source": "corridor-centre"},
    "rails":    {"y": [...], "x": [...], "z": [...], "source": "track_geometry"},
    "axis":     {"y": [...], "x": [...], "z": [...], "source": "panel-axis"}
  }
},
"tunnel": {
  "half_width": 1.36,
  "z_low": 0.10,
  "z_high": 3.70,
  "rail_height": 0.16,
  "exclude_contact": true,
  "spans": [[-39.5, -37.5]],
  "bins_blocked": 2,
  "bins_total": 46
}
```

`GET /set` дополнительно принимает `tunnel_half` (0.5…2.5), `tunnel_low` (−0.5…1.0),
`tunnel_high` (1.0…5.0), `tunnel_contact` (0/1) и возвращает пересчитанный `tunnel`
и `path`. Пересчёт занимает те же ~0.2 с, что и сейчас.

## Клиент

- группа панели **«Линия хода»**: чекбокс `показывать`, селект источника
  (`коридор` / `рельсы` / `ось` / `сравнение — все три`), слайдер толщины;
- группа **«Туннель безопасности»**: чекбокс `показывать`, слайдеры полуширины,
  низа и верха, чекбокс `исключать контактный рельс`, строка со сводкой
  («занято 2 из 46 бинов, 4.0 м»);
- линии — плоские ленты (как раньше у рельсов: толщину `LineBasicMaterial` WebGL
  игнорирует), цвет: коридор — зелёный, рельсы — жёлтый, ось — голубой;
- каркас туннеля — `LineSegments` по рёбрам сечений, `depthWrite: false`;
- точки внутри туннеля красятся красным **на клиенте**: по `path` интерполируем
  `x(y)` и проверяем `|x − x_пути| ≤ half_width` и высоту в границах — это дешевле,
  чем гонять маску с сервера (~10 мс на 340 тыс. точек).

## Проверка

1. Юнит-тесты (`tests/test_zones.py`): линия коридора лежит внутри стен и не
   выходит за коридор; туннель не задевает рельсы и контактный рельс в их
   нормальном положении; исключение платформы работает; вырожденные входы.
2. На реальных данных (`doubleT_obstacle`): объект на `y ≈ −38` (высота 1.0 м,
   `x 4.5…5.08`) **попадает** в туннель при оси 4.05 и **не попадает** при оси 3.31.
3. На заведомо свободном участке (первые 20 м при правильной оси) — ноль занятых бинов.
4. Клиент: скриншоты (линия и каркас видны), переключение вариантов, отсутствие
   ошибок в консоли, сверка занятых участков с `/meta`.

## Вне объёма (сознательно не делаем)

- автоматический выбор «лучшего» варианта линии — сравниваем глазами и оставляем
  один вручную;
- учёт вертикальных кривых пути (профиль) — линия идёт по плоскости пола;
- детекция движущихся объектов по кадрам (сейчас всё считается один раз по bag'у);
- габариты станций/платформ как отдельный режим — только исключение края платформы.
