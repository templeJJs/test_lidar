# 3D-объекты пути в вьюере (рельс, шпалы, пол) — дизайн

Дата: 2026-09-15
Статус: черновик на ревью
Файлы: см. раздел «Реализация» (по умолчанию — новые, чужие файлы не трогаем)

## Проблема

Вьюер показывает только облако точек. Рельс и шпалы не читаются как объекты: «лента рельсов»
нарисована как `z_floor(y) + 0.16` и садится на **0.3 м (doubleT_obstacle) и 0.7 м (doubleT_platform)
ниже** наблюдаемой головки. Нет режима, в котором видно только геометрию пути, и нет возможности
переключать элементы (точки / рельсы / шпалы / пол).

Цель: показать рельс, шпалы и пол **полноценными 3D-объектами**, с честной пометкой «измерено» или
«взято из стандарта», плюс тумблеры и отдельный вид «чистое поле» — только объекты, без облака.

## Установленные факты (измерено, не предположения)

Наблюдаемо лидаром: верх головки (высота над прилегающей поверхностью **0.159–0.186 м**, сходится
со стандартной высотой головки Р65 = 0.172 м), ширина и плоскостность площадки, ось пути, колея,
уклон. Сенсор стоит **1.11 м** над верхом головки (platform) и **1.51–1.59 м** (obstacle).

Не наблюдаемо: шейка и всё ниже **~35–40 мм** под верхом головки — в тени свеса головки
(расчёт: видимая глубина Δ ≈ H·(|x_web| − |x_кромки|)/|x_кромки|). Значит шейка и подошва берутся
из стандарта — это не упрощение, а единственная возможность.

Шпалы: **не наблюдаются**. Периодической структуры нет ни в одной из 70 боковых полос ни в одной из
6 записей (амплитуда компоненты 0.55 м — 2–5 мм, фаза случайная R = 0.32–0.36, шаг нерегулярный,
std 0.24–0.26 м). Инъекционный тест: впрыснутая периодика восстанавливается на 60–70 % истинной
амплитуды, то есть реальная шпала (30–50 мм) дала бы в 3–7 раз выше шума; порог обнаружения
~13–16 мм. Видимая поверхность пола гладкая (4–6 мм на масштабе 5–20 см) — бетоноподобная, не балласт.

Колея: норматив — расстояние между **внутренними (рабочими) гранями головок на уровне 13 мм ниже
поверхности катания** (ПТЭ п. 45; распоряжение ОАО «РЖД» № 2288р, п. 2.1.21), номинал
1520 (−4/+8) мм. Ось—ось = 1520 + ширина головки = **1592.5–1595 мм** (Р65). Прямое измерение
внутренних граней в наших облаках даёт **1520 и 1522 мм**. Наши прежние 1539/1556/1572 — не другая
колея, а смещённая внутрь оценка центра головки (подуклонка 1:20 = 2.86°): сдвиг 75 / 52 / 30 %
от полуширины головки.

## Объекты

| объект | геометрия | происхождение |
|---|---|---|
| Рельс | профиль по кадрам: ось, колея, высота верха над прилегающей поверхностью, уклон; **экструзия вдоль оси пути**; ниже 35–40 мм от верха — стандартный Р65 (шейка, подошва) | головка — **измерено**; шейка/подошва — **ГОСТ Р65** |
| Шпалы | стандартные боксы по оси пути, шаг и размеры по стандарту | **ГОСТ** (в данных не наблюдаются) |
| Пол/балласт | плоскость по `floor.a/b` из метаданных, в пределах коридора | **измерено** (модель плоскости) |
| Уклонка | наклон сечения 1:20 по стандарту | **ГОСТ** |

Опорная плоскость для рельса — **прилегающая поверхность в 0.10–0.24 м внутрь от центра**, а не
`z_floor(y)`; иначе объект садится ниже наблюдаемой головки.

## Интерфейс

- Тумблеры: **точки**, **рельсы**, **шпалы**, **пол**; у каждого объекта — пометка «измерено / ГОСТ»,
  видимая в легенде.
- Отдельный вид **«чистое поле»**: облако скрыто, фон нейтральный, камера вписана по габариту
  объектов. Выход из вида возвращает видимость точек по состоянию тумблера. Разрез (`drawSection`)
  гейтится тем же флагом `points.visible`.
- Шаг слайдера дистанции пересобирает геометрию → старая геометрия и материал диспоузятся,
  видимость сохраняется.

## Реализация

Точки встраивания в существующем вьюере (найдены разбором `web/app.js` и `web_viewer.py`):
строить меши в `buildRails`-подобных функциях (`app.js:676, 207, 406`), **не** в `loop()` и **не**
в `applyFrame`; тумблеры — через `applyVisibility()` (`app.js:409-411`); «чистое поле» — пункт в
`PRESETS` (`app.js:299`) плюс вынести `fit` (`app.js:312-324`) в `fitBox(box)`; новый поток данных в
`/meta`.

**Ограничение:** `web/app.js` и `web_viewer.py` — файлы параллельного агента, он правит их прямо
сейчас. Поэтому по умолчанию делаем **отдельным вьюером `track3d`** (свой сервер + своя страница,
только новые файлы, нулевой риск столкновения), а перенос в общий вьюер — отдельной задачей после
того, как параллельный агент закоммитит свои правки.

## Технические ловушки (из разбора вьюера)

1. Данные в three.js идут **как есть, Z вверх** — ориентация держится на глобальной мутации
   `THREE.Object3D.DEFAULT_UP` (`app.js:15`). Отсюда: `ExtrudeGeometry` выдавит профиль вдоль **+Z**
   (рельс встанет вертикально) — нужен ручной sweep или `rotateX(-π/2)`; `BoxGeometry(w,h,d)` кладёт
   «высоту» в **Y** (шпала станет вертикальной стенкой) — нужно `BoxGeometry(длина_x, ширина_y,
   высота_z)`; `setFromUnitVectors((0,1,0), dir)` неприменим.
2. Лента рельсов идёт с `depthTest:false` + `renderOrder:10` («поверх всего»). Развести порядки:
   пол 0 / шпалы 5 / рельсы 6 / лента 10 — либо гасить ленту в «чистом поле».
3. Сетка сейчас на `z = 0` (плоскость сенсора), а пол — `z ≈ −1.886 + 0.0216·y`: после появления
   объекта «пол» сетка будет висеть заметно выше. Решить заранее.
4. Буферы кадра (`DynamicDrawUsage`, `setDrawRange`) аллоцируются один раз — per-frame геометрии
   объектов быть не должно, только статика.
5. Дефект существующего вьюера: `app.js:141` читает `meta.rail_height`, а `/meta` его не отдаёт →
   всегда заглушка 0.16.

## Правки колеи (входят в тот же объём)

1. `random_state=0` в RANSAC оценки плоскости (`visualize_bag.py:191`): разброс между прогонами
   σ 11.7 → 0, размах 55 → 0 мм; цена — **+5 мм** к печатаемому значению.
2. Локальный центр нити: медиана по Y-окну **W = 1.0–1.5 м** с 3 итерациями отбраковки по MAD
   вместо медианы в ±0.5 м. Маску (`rail_radius=0.04`, `dz` −0.02…+0.12) и состав точек не менять.
   Сдвиг **−3.9…+3.8 мм**, сжатие разброса ×1.2–2.8.
3. База отсчёта: мерить **внутренние грани** головки на уровне площадки → 1520–1522 мм без поправок.
4. `db_eps` не трогать (на 5 записях из 6 — no-op, слияние путей начинается с 1.5). Отдельным
   решением: на `doubleT_obstacle` поставить 1.0 — там это исправляет выбор «своей» пары и даёт
   1507.6 мм при σ по кадрам 1.24 мм.

## Приёмка

1. Объект «рельс» совпадает с реальными точками головки в пределах измеренной ширины головки
   (проверяется численно: доля точек головки, попавших внутрь контура профиля).
2. Тумблеры переключают элементы независимо и не ломают текущие режимы раскраски.
3. «Чистое поле»: облако скрыто, камера вписана по объектам, разрез отключён, при выходе состояние
   восстанавливается.
4. Колея по новой базе на `doubleT_platform` — **1520 ± 10 мм**; разброс между прогонами — **0**.
5. Тесты: численные проверки профиля и колеи запускаются как обычный скрипт, без GUI.
